## 2. ✅ Q-7 — 관리자가 쿠폰 발급분을 회수하고, 발급분 없는 정의를 삭제한다 — ⏳ **배포 대기**

### 2-1. 착수 전 실측 (WA §1-3-1)

| 백로그의 주장 | 판정 |
|---|---|
| 쿠폰 API 는 생성·발급·가입 지정뿐 | **참** — 보유자를 보는 화면도 없었다 |
| 쓰인 발급분은 주문이 가리켜 지울 수 없다 | **참** — `orders.member_coupon_id`(V46, FK 없음) → 취소·반품의 `restore` 대상 |
| «미사용 회수 + 정의 비활성» 일 가능성이 크다 | **반만 참** — 행 삭제를 고르면 «회수 → 정의 삭제» 로 끝나 비활성 상태가 필요 없다 |
| (암묵) 미사용이면 주문과 무관하다 | 🔴 **거짓** — 전체 취소·반품이 쿠폰을 되돌려 놓은 주문이 **미사용 행을 가리킨다** |

실측(쿠폰별 발급 / 사용 / 가리키는 주문): `테스트 쿠폰` **1 / 0 / 2** · `ZZ-발급마감쿠폰테스트` **1 / 0 / 5** ·
`가입 쿠폰 10000원` 3 / 1 / 2. ⚠ 그 주문들은 이미 전부 되돌렸으므로(`restore` 는 «남은 것이 없을 때» 만 불린다)
**미사용 행을 지워도 다시 불릴 일이 없다** — 불려도 경고 로그만 남기고 넘어간다.
정의 삭제는 발급분이 하나라도 있으면 FK(`fk_member_coupon_coupon`)가 막는다.

### 2-3. 무엇을 고쳤나 (`3becb7b`)

- **API** — `GET /api/admin/coupons/{id}/issued`(쓰인 것도 함께) · `DELETE …/issued/{memberCouponId}`(미사용만, `COUPON-409U`) ·
  `DELETE /api/admin/coupons/{id}`(발급분 있으면 `COUPON-409D`, 가입 쿠폰이면 `COUPON-409W`).
- 🔴 **회수의 경합** — «읽고 확인한 뒤 지우기» 면 관리자가 미사용을 읽은 순간 고객이 주문해 **주문이 가리키는 행이 사라진다.**
  → `delete … where id = :id and usedAt is null` 로 조건을 문에 넣었다(Oracle 이 잠금을 기다린 뒤 조건을 다시 평가한다).
  사전 `isUsed` 확인은 흔한 경우에 뜻 있는 409 를 주려는 것이다.
- **가입 쿠폰 삭제는 막는다** — 지우면 가입 자동 발급·홈 «가입하면 쿠폰» 안내가 **조용히 꺼진다.** 해제 버튼이 그 결정을 묻는다.
- **감사** — `COUPON_REVOKE`(대상 **회원**, 발급 `COUPON_ISSUE` 와 짝) · `COUPON_DELETE`(대상 쿠폰). detail 은 기존 `describe`(«이름 · 3000원»).
  **V65** 가 `ck_admin_audit_action` 을 넓힌다(구 jar 영향 없음 — 넓히는 방향). `WriteEndpointAuditCoverageTest` 목록에 둘 추가.
- **member 공개 API** — `MemberService.loginIdsOf(Collection)`(빈 목록이면 쿼리 안 함 — Oracle 빈 `IN ()`).
- **화면** — 쿠폰 줄마다 「보유자」 펼치기 · 쓰인 줄은 «사용함 · 날짜»(회수 버튼 없음) · 0장일 때만 「쿠폰 삭제」(`btn-danger`)와
  «왜 삭제 버튼이 없나» 한 줄. 감사 라벨·배지(`badge-danger` 둘)·분류(쿠폰). DESIGN 쿠폰 행 갱신.
