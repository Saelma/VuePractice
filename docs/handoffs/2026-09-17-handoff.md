## 2. ✅ Q-7 — 관리자가 쿠폰 발급분을 회수하고, 발급분 없는 정의를 삭제한다

### 2-1. 착수 전 실측 (WA §1-3-1)

| 백로그의 주장 | 판정 |
|---|---|
| 쿠폰 API 는 생성·발급·가입 지정뿐 | **참** — 보유자를 보는 화면도 없었다 |
| 쓰인 발급분은 주문이 가리켜 지울 수 없다 | **참** — `orders.member_coupon_id`(V46, FK 없음) → 취소·반품의 `restore` 대상 |
| «미사용 회수 + 정의 비활성» 일 가능성이 크다 | **반만 참** — 행 삭제를 고르면 «회수 → 정의 삭제» 로 끝나 비활성 상태가 필요 없다 |
| (암묵) 미사용이면 주문과 무관하다 | 🔴 **거짓** — 전체 취소·반품이 쿠폰을 되돌려 놓은 주문이 **미사용 행을 가리킨다** |

실측(쿠폰별 발급 / 사용 / 가리키는 주문): `테스트 쿠폰` **1 / 0 / 2** · `ZZ-발급마감쿠폰테스트` **1 / 0 / 5** ·
`가입 쿠폰 10000원` 3 / 1 / 2. ⚠ 그 주문들은 이미 전부 되돌렸으므로(`restore` 는 «남은 것이 없을 때» 만 불린다)
**미사용 행을 지워도 다시 불릴 일이 없다** — 불려도 경고 로그만 남기고 넘어간다.

| 질문 | 결정 | 버린 안 |
