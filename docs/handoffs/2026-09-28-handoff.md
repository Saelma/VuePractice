- 🔴 그래서 이월 #1·#5·#8 이 써 온 **«재부팅이 없으면 다음 날 같은 시각」 은 처음부터 성립하지 않는 전제**였다.

- **결과**: 하루 주기 배치(알림 정리)는 **«그날 부팅 + 10분」 에 하루 한 번**만 돈다(fixedDelay 24시간은 다음 부팅 전에 절대 안 온다).
  시간 주기 배치(상품 purge · 이미지 정리)는 **부팅 + 5분 + n시간**. 주말·휴일에는 **아무것도 안 돈다** — 대신 다음 부팅 회차가 밀린 것을 **한꺼번에** 지운다(오늘 51건이 그 모양).
- ⚠ **해는 없다** — 보관 기간 판정이 «경과 시간」 이라 늦게 돌아도 지울 것은 전부 지운다. 고칠 것이 아니라 **예측 문장을 고칠 것**이다.

### 2-5. 진단법 (→ TROUBLESHOOTING 후보)

«배치가 예상 시각에 안 돌았다 / 한꺼번에 많이 지웠다」 를 보면, 저널보다 먼저 **VM 이 켜져 있었나** 를 본다:

```bash
LC_ALL=C sar -f /var/log/sa/sa$(date -d '2026-09-24' +%d) | head    # 그날 파일이 이번 달 것인가 · RESTART 와 샘플 구간
ls -la --time-style=full-iso /var/log/sa/ /var/log/ | grep -E 'sa[0-9]+|messages'   # 마지막 기록 시각
last -x -F | head                                                   # 부팅 줄 — ⚠ «기록 없음» 은 «켜져 있었다」 가 아니다
```

⚠ **이 절이 원본이다** — TROUBLESHOOTING 에는 «증상 → 의심 → 명령」 한 줄과 여기로 가는 링크만 둔다(CLAUDE.md). ✅ **옮겼다**(§4-2 — 「배치가 며칠 동안 아예 안 돌았다」 행).
