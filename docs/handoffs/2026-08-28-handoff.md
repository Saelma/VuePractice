## 2. G-6 이 무엇을 했나 — **설계 판단 넷**

등급의 효과가 **적립률 하나**뿐이었다. 무료배송 기준 인하를 더해 **둘**로 만들었다:
**BRONZE 0% · SILVER 20% · GOLD 40% · VIP 60%**(기본 기준 30,000원 → 24,000 · 18,000 · 12,000).
**스키마 변경 없음** — enum 상수라 V 번호가 붙지 않는다.

### 2-1. 🔴 경계를 **양쪽에서** 지켰다 — 백로그는 한쪽만 적었다

백로그 G-6 의 ⚠ 는 *"`ShippingPolicy`(global)가 `MemberGrade`(point)를 알면 안 된다 — 등급이 아니라
「적용할 기준 금액」을 넘겨받는 형태여야 한다"* 였다. 그대로 갔다:

```java
public long feeFor(long itemsTotal, long freeThresholdToApply)      // 금액을 받는다
public long discountedThreshold(long baseThreshold)                  // 등급 → 금액은 point 가 한다
```

🔴 **그런데 뒷면이 하나 더 있었고, 그건 항목에 없었다** — *«그럼 `MemberGrade` 는 30,000 을 아는가»*.
**모르게 뒀다.** 등급이 갖는 것은 **인하율(비율)** 뿐이고 «원» 은 설정
(`glassvue.shipping.free-threshold`)에 **한 곳**만 산다. 금액을 enum 에 적었으면 무료배송 기준이
**설정과 enum 두 곳**에 살고, 한쪽만 고쳐지면 조용히 어긋난다 — **§I-1 이 사본 넷 때문에 난 사고다.**

⚠ 그래서 `ShippingPolicy.feeFor(itemsTotal, freeThresholdToApply)` 는 **«누구의» 기준인지 모른다.**
등급이 늘어나든 혜택 규칙이 바뀌든 **global 은 안 고쳐진다.** 그게 이 형태를 고른 값이다.

### 2-2. 🔴 항목이 안 적은 것 — **`amountUntilFree` 도 같이 고쳐야 했다**

백로그는 `feeFor` 만 말했다. 그런데 화면의 *"N원 더 담으면 무료배송"* 은 **다른 메서드**가 낸다.
한쪽만 등급 기준을 쓰면 — **«12,000원 더 담으면 무료배송» 이라 말하면서 이미 무료**다.

⚠ **짝이 있는 계산은 함께 기준을 받는다**(WA §1-2-1 의 또 다른 얼굴: 짝을 나란히 놓고 본다).
🔴 이 자리는 **테스트로도 안 잡혔을 것**이다 — 둘 다 «맞는 값» 을 돌려주고, **서로 안 맞을** 뿐이다.
그래서 `ShippingPolicyTest.feeAndRemainingAgreeOnSameThreshold` 가 **«무료인데 아직 남았다고 말하는»
조합이 없는지**를 총량으로 훑는다(합계 × 기준을 돌며 둘의 답이 어긋나는지 본다).
⚠ 같은 파일의 `noArgFormDelegatesToConfigured` 는 **인자 없는 옛 형태가 설정값으로 부른 것과 같다**를
지킨다 — 오버로드를 더하면서 **두 경로가 갈리는 것**이 그 다음 함정이라서다.

### 2-3. 좁은 공개 API 하나 — `PointService.gradeOf`

`myAccount` 를 부르면 «다음 등급까지 얼마» 같은 **표시용 계산**까지 딸려 온다. 부르는 쪽은 등급
하나만 필요하다 → `balanceOf` 와 같은 성격으로 **좁게** 열었다.

🔴 **계정이 없으면 `BRONZE` 를 돌려주고 저장하지 않는다.** 여기서 계정을 만들면 **장바구니를 여는
것만으로** 적립금 계정이 생긴다(`myAccount` 가 «빈 계정을 보여주되 save 하지 않는다» 로 정한 것과
같은 판단).

### 2-4. ⚠ **`cart → point` 의존이 새로 생겼다**

장바구니가 등급을 알아야 배송비를 낸다. `order → point` 는 이미 있었다.
🔴 **주문의 `shipping_fee` 는 스냅샷이라 등급이 올라도 소급되지 않는다** — 정책이 바뀌어도 과거
주문의 배송비가 안 바뀌는 것과 같은 규칙이고, G-4 결정 2(「무료배송 기준 소급 안 함」)와 같은 방향이다.

⚠ **장바구니와 주문이 같은 값을 두 번 계산한다**(`CartResponse.shippingFee` ↔ `OrderService`).
**그게 원래 구조였고 G-6 이 그걸 바꾸는 항목은 아니다** — 다만 이제 **둘 다 등급을 읽으므로**,
한쪽만 고치면 «장바구니에선 무료였는데 주문서에선 3,000원» 이 된다.

화면 쪽은 한 줄이다 — `PointPanel` 에 «24,000원 이상 무료배송». 🔴 **화면은 인하율도 기본 기준도
모른다**(서버가 `freeShippingThreshold` 로 준다). `PointPanel.test.js`(신설)가 지키는 것은
«금액이 맞나» 가 아니라 **«화면이 계산을 다시 하지 않는가»** 다.
