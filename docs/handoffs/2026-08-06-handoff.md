## 2. G-3 묶음 — 착수 전 실측

> WA §1-3: 문서의 **결론이 맞아도 이유는 틀릴 수 있다.** 8/05 에 세 번 데였다.

### 2-1. 실측 — 문서가 적은 것이 맞는가

| 확인한 것 | 실측 | 출처 |
|---|---|---|
| `inquiry.product_id` 가 정말 필수인가 | **필수** — 엔티티 `nullable = false, updatable = false`, DDL `RAW(16) NOT NULL` | `Inquiry.java:30`, `V1__init.sql` |
| 그 컬럼이 FK 인가 | **아니다** — DDL 주석에 *"FK 아님(느슨한 참조)"*. 인덱스만 있다(`idx_inquiry_product`) | `V1__init.sql`, `V2__add_query_indexes.sql` |
| 문의 API 전수 | `POST`·`GET /products/{productId}/inquiries` · `PUT`·`DELETE /inquiries/{id}` · `POST /inquiries/{id}/answer` — **전부 상품 경로 아래이거나 단건이다** | `InquiryControllerImpl.java` |
| 관리자 문의 목록 | **없다** — `/api/admin/**` 아래 문의 컨트롤러가 없다 | `find … grep -i admin` 전수 |
| 내 문의 목록 | **없다** — `findByAuthorId` 는 `List` 반환에 페이징이 없고, 주석에 **회원 삭제 정리용(F-1)** 이라 못박혀 있다 | `InquiryRepository.java` |
| 조회 리포지토리 능력 | `InquiryRepositoryCustom` 의 메서드는 `findByProduct` **하나** — 관리자 목록은 새로 짜야 한다 | `InquiryRepositoryCustom.java` |
| 다음 마이그레이션 번호 | 최신이 `V41__add_review_hidden.sql` → **다음은 `V42`** | `db/migration/` |

**결론: BACKLOG G-3 의 2026-08-03 실측이 지금도 맞다.** 관리자는 **상품 상세를 통해서만** 문의에
답할 수 있고, 상품 없는 문의는 **답할 경로가 아예 없다.**

⚠ **다만 문서가 안 적은 것이 하나 나왔다** — 답변 API(`POST /inquiries/{id}/answer`)는 **상품 경로
아래가 아니다.** BACKLOG 가 *"답변 API 는 재사용된다"* 고 적은 근거가 실제로 확인됐고, 동시에
**관리자 목록만 만들면 답변까지 바로 붙는다**는 뜻이다 — 새로 만들 것은 **목록(조회)뿐**이다.

## 3. 작업 순서 (착수 전 계획)

> 순서가 뒤집히면 *"넣기만 하고 답을 못 하는"* 상태가 생긴다 — 그래서 **관리자 목록이 먼저**다.

1. **관리자 문의 목록** (선행) — `GET /api/admin/inquiries` (상태 필터) + 화면. 답변은 기존 API 재사용.
2. **일반 문의** — `V42` 로 `product_id` NOT NULL 해제 + 작성 API·진입점.
3. **내 문의 목록** — 2 를 넣으면 **볼 데가 필요해진다.** 1·2 를 닫고 판단한다.

### 3-1. 착수 전 결정 (사용자와 확정, 2026-08-06)

| 결정 | 무엇으로 | 근거 |
|---|---|---|
| 관리자 목록 기본 필터 | **미답변(`WAITING`)** | 관리자가 목록을 여는 이유가 *"답할 게 뭐가 남았나"* 다. 필터는 리뷰 관리와 같은 모양(`@RequestParam(required=false)` → **null 이면 전체**)이라 상태 탭을 그 위에 얹는다 |
| 문의 유형 | **둔다** (`inquiry_type`) | 일반 문의는 유형이 없으면 관리자가 목록에서 성격을 못 가린다 |
| 문의 숨김(B-18 잔여) | **이번엔 안 붙인다** | G-3 이 푸는 것은 *"답할 경로가 없다"* 다. 숨김은 리뷰 쪽 패턴이 이미 있어 나중에 따로 붙여도 싸다 |
| 작업 브랜치 | **`g3-inquiry-support`** (신설) | `b19-stock-history` 는 그 뒤 B-17·B-18·문서까지 얹혀 **이름이 실제와 어긋나 있었다**. `main` 과 완전 동일한 지점에서 판다 |

⚠ **`inquiry_type` 은 CHECK 제약이 따라온다 — 값 집합을 처음에 넉넉히 잡는다.**
Oracle 에서 enum 값을 나중에 늘리면 `ddl-auto=update` 가 CHECK 를 **못 고쳐** `ORA-02290` 이 난다
(수동 `ALTER` 가 필요하다 — 기존에 데인 자리). 그리고 **기존 행 백필**이 함께 온다:
지금 문의는 전부 상품 문의라 `PRODUCT` 로 채운 뒤 `NOT NULL` 을 건다(V42 에서 순서를 지킬 것).
