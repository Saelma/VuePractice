### 3-1. 착수 전 결정 (사용자와 확정, 2026-08-06)

| 결정 | 무엇으로 | 근거 |
|---|---|---|
| 관리자 목록 기본 필터 | **미답변(`WAITING`)** | 관리자가 목록을 여는 이유가 *"답할 게 뭐가 남았나"* 다. 필터는 리뷰 관리와 같은 모양(`@RequestParam(required=false)` → **null 이면 전체**)이라 상태 탭을 그 위에 얹는다 |
| 문의 유형 | **둔다** (`inquiry_type`) | 일반 문의는 유형이 없으면 관리자가 목록에서 성격을 못 가린다 |

⚠ **`inquiry_type` 은 CHECK 제약이 따라온다 — 값 집합을 처음에 넉넉히 잡는다.**
Oracle 에서 enum 값을 나중에 늘리면 `ddl-auto=update` 가 CHECK 를 **못 고쳐** `ORA-02290` 이 난다
(수동 `ALTER` 가 필요하다 — 기존에 데인 자리). 그리고 **기존 행 백필**이 함께 온다:

### 5-2. 브라우저 검증 — 사용자 확인 + **로그로 뒷받침**

사용자 판정: *"잘 되는 것 같다 · 작성자 계정으로 하려니 막은 것도 잘했고 · 알림도 잘 간다."*
⚠ 화면 인상만 적지 않고 **그 시각 로그에서 무엇이 돌았는지**를 찾아 붙였다:

| 무엇 | 로그 실측 |
|---|---|
| **본인 문의 답변 차단** | `BusinessException: INQUIRY-403S - 본인이 등록한 문의에는 답변할 수 없습니다` — **16:58:35 · 16:58:38 두 번** |
| **답변 저장 + 알림** | `Inquiry answered: id=019fd615… by=019f6450… **first=true**` (17:00:06) |

🔴 **`first=true` 가 이 검증의 핵심**이다. 알림은 **첫 답변에서만** 나가는데(B-15), 화면에서 알림이
왔다는 것과 *"첫 답변 판정이 맞게 돌았다"* 는 다른 말이다. 판정이 `answer()` **뒤**로 밀리면 영영
`false` 가 되어 알림이 안 나가고, 그때도 답변 기능은 멀쩡해 보인다 — 그 한 줄이 실제로 살아 있음을
`first=true` 가 보여 준다.

⚠ **차단은 «관리자 권한» 이 아니라 «본인 문의» 규칙이 잡았다.** 둘 다 403 이라 화면에서는 구분이 안
되는데, 로그의 `INQUIRY-403S` 로 갈렸다 — `/api/admin/**` 의 ADMIN 규칙이었다면 스프링 시큐리티가
막아 이 예외 자체가 안 찍힌다.

### 5-3. 검증 잔재 — **문의 1건 · ⚠ `ZZ` 가 안 붙었다**

```
KST   STATUS     SEC AUTHOR      TITLE
16:59 ANSWERED     1 김기현팀3   이거 자바아닌데?     (답변 있음)
```

- 오늘 생긴 문의는 **이 1건**이고 **비밀글**이다. `stock_history` 같은 부수 변경은 없다(조회 기능이라
  쓰는 경로가 없다).
- ⚠ **`ZZ` 접두사가 없다** — 사용자가 화면에서 직접 만든 것이라 WA §3-1 규약이 적용되지 않았다.
  `title like 'ZZ%'` 로 세면 **0건**이 나온다. 2026-07-22 에 데인 것과 **같은 종류**다:
  *"ZZ 로 세는 쿼리는 ZZ 를 안 붙인 잔재를 못 잡는다."*
  → 그래서 여기에 **날짜와 제목을 그대로 적어 둔다**(세는 쿼리로는 다시 못 찾는다).
  → 문의는 **삭제 API 가 있다**(`DELETE /api/inquiries/{id}`, 관리자 가능) — 주문과 달리 지울 수 있다.
    **지울지는 사용자 결정**이라 지금은 두었다.
