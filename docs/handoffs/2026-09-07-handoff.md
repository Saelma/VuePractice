## 4. 🔴 되물렸다 — **「데이터가 없어서」와 「틀려서」는 다르다**

§3 을 커밋한 뒤 사용자가 말했다: *"수요/매출 예측이랑 연관분석도 넣어놔 나중에 데이터 생성
로직 짜가지고 할 거니까"*.

⚠ **내 «안 한다» 는 근거가 «데이터가 없다» 하나였다.** 그건 **영구 결격이 아니라 선행 조건**이다 —
데이터를 만들면 열린다. 🔴 **❌ 로 닫아 두면 다음 사람이 «이건 안 되는 것» 으로 읽는다.**

→ **❌ → ⏸ 선행 대기**로 고치고 셋을 세웠다: **N-4 연관분석**(중~대) · **N-5 예측**(중) ·
**N-6 분석용 데이터 생성**(중, 앞의 둘의 선행).

### 4-1. 🔴 그러면서 **이름값을 바로잡아야 했다 — N-4·N-5 는 AI 가 아니다** (N-00)

절이 「AI 연동」에서 시작했지만:

| 항목 | 무엇으로 푸나 | LLM 을 부르나 |
|---|---|---|
| N-1·N-2·N-3 | Claude API | ✅ |
| **N-4 연관분석** | **Apriori/FP-Growth** — 계수(counting) 알고리즘 | ❌ |
| **N-5 예측** | 이동평균·선형회귀 등 통계 | ❌ |

**흐리면 둘이 어긋난다**: ①**배선을 잘못 공유한다** — N-4·N-5 는 `global/ai` 도 API 키도 타임아웃
폴백도 필요 없다. ⚠ **N-1 을 먼저 한다고 N-4 가 쉬워지지 않는다.** ②**결과의 성격을 착각한다** —
LLM 이 «지어내는» 것과 알고리즘이 «세는» 것은 다르다.

### 4-2. 🔴 N-4 의 함정 — **내가 심은 규칙을 도로 찾는다**

생성 데이터로 연관분석을 돌리면 나오는 규칙은 **전부 N-6 이 심은 것**이다. 「A 를 산 사람은 B 를
산다」가 나와도 그것은 고객에 대한 발견이 아니라 **생성기 설정의 반향**이다.
⚠ **이것을 잊으면 «우리 고객은 …» 이라는 문장이 생기고, 그 문장은 거짓이다.**

**그래서 목적을 바꿔 적었다:**

| 얻는 것 | 어떻게 |
|---|---|

## 9. 후보 ④ — **O 축을 열었다**: 「빠뜨리면 어느 쪽으로 넘어지나」

M 절이 *"다음 축은 이 방식(**원장 세기**)이 아니라 **다른 각도**에서 와야 한다"* 고 자기 한계를
적어 뒀다. → 🔴 **«무엇을 세나» 가 아니라 «무엇이 기본값인가» 를 물었다.**

> **축의 질문**: 이 목록은 **손으로** 유지된다 — **빠뜨렸을 때 어느 쪽으로 넘어지나?**
> 안전한 쪽(터진다·막힌다)이면 빠뜨림이 **스스로 드러나고**, 위험한 쪽(열린다·통과한다)이면
> **아무도 안 묻는다.**

⚠ **새로 지은 각도가 아니다 — 이미 두 번 이걸로 다쳤다.** `existsPurchase` 가 `DELIVERED` 를
빠뜨려 **배송완료 고객이 리뷰를 못 썼고**(07-20·07-23, **같은 자리가 두 번**), 08-11 에
`OrderStatus.purchaseProven()` 으로 **모양 자체를 바꿔** 고쳤다(상수별 플래그 → 새 상태가
반드시 결정을 받는다). 🔴 **이 축은 «그 모양이 또 어디에 있나» 를 센다.**

### 9-1. O-1 — `SecurityConfig` 의 마지막 줄이 **`.anyRequest().permitAll()`** 이다

| 무엇 | 값 |
|---|---|
| `@XxxMapping` 엔드포인트 | **123개** |
| `requestMatchers` 줄 | **37개** |
| 매처에 안 걸려 **기본값으로 열리는** 엔드포인트 | **16개** |
| `@PreAuthorize` 를 쓰는 파일 | 🔴 **0개** |

**살아 있는 서버(`127.0.0.1:8080`)로 34건을 찔렀다** — 비로그인으로:

| 무엇 | 결과 |
|---|---|
| 인증이 필요해야 할 GET 18개 | ✅ **전부 401** |
| 공개여야 할 GET 7개 | ✅ **전부 200** |
| 관리자 쓰기 POST 9개 | ✅ **전부 401** |

⚠ **쓰기는 «존재하지 않는 UUID» 로 찔렀다** — 혹시 인증이 안 막더라도 **404 로 끝나 아무것도
안 바뀌게** 하는 설계다. 🔴 **찌르는 순서가 그 자체로 안전장치여야 한다.**

→ ✅ **지금은 새는 곳이 없다.** 🔴 **그래서 결과물이 «고침» 이 아니라 «덮개» 다.**

### 9-2. 처방은 **08-11 과 같은 것** — `EndpointAuthCoverageTest`

핸들러 매핑에서 엔드포인트를 **전부 꺼내** 비로그인으로 한 번씩 부르고, **401 이 아니면
`PUBLIC` 목록에 선언돼 있어야** 통과한다. 새 엔드포인트가 생기면 **반드시 둘 중 하나를 결정**하게 된다.

- ⚠ **매처 규칙을 테스트에 베끼지 않았다** — 판정은 **실제 응답**으로 한다.
  🔴 **베끼면 `SecurityConfig` 와 갈라지고, 갈라진 순간 «둘 다 초록인데 운영은 열린다».**
- ⚠ **`PUBLIC` 은 «지금 열려 있는 것» 이 아니라 «열려 있어야 하는 것»** 으로 하나씩 판단해 채웠다.
  🔴 **실측을 베끼면 현재 상태를 복사할 뿐 아무것도 안 지킨다.**
- **되돌려서 확인**: `PUBLIC` 에서 한 줄 빼면 *"매처가 없어 비로그인에 열렸다"*, 401 인 경로를
  `PUBLIC` 에 넣으면 *"공개라고 적어 뒀는데 막힌다"*, 원본은 통과. **셋이 갈린다.**
- ⚠ 판정은 `tests="1" skipped="0" failures="0"` 으로 했다 — **`BUILD SUCCESSFUL` 을 «돌았다» 로
  읽지 않는다**(09-02 가 그것에 물렸다). 컨텍스트를 띄우므로 **1분 30초~2분**.
- ⚠ **`RequestMappingHandlerMapping` 은 빈이 하나가 아니다**(actuator 가 따로 등록한다) —
  `@Qualifier("requestMappingHandlerMapping")` 없이는 **컨텍스트가 아예 안 뜬다**(첫 실행이 그렇게 죽었다).
