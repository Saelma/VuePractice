## 4. 🔴 되물렸다 — **「데이터가 없어서」와 「틀려서」는 다르다**

§3 을 커밋한 뒤 사용자가 말했다: *"수요/매출 예측이랑 연관분석도 넣어놔 나중에 데이터 생성
로직 짜가지고 할 거니까"*.

⚠ **내 «안 한다» 는 근거가 «데이터가 없다» 하나였다.** 그건 **영구 결격이 아니라 선행 조건**이다 —
데이터를 만들면 열린다. 🔴 **❌ 로 닫아 두면 다음 사람이 «이건 안 되는 것» 으로 읽는다.**

→ **❌ → ⏸ 선행 대기**로 고치고 셋을 세웠다: **N-4 연관분석**(중~대) · **N-5 예측**(중) ·
**N-6 분석용 데이터 생성**(중, 앞의 둘의 선행).

### 4-1. 🔴 그러면서 **이름값을 바로잡아야 했다 — N-4·N-5 는 AI 가 아니다** (N-00)

절이 「AI 연동」에서 시작했지만:

| 항목 | 무엇으로 푸나 | LLM 을 부르나 |
|---|---|---|
| N-1·N-2·N-3 | Claude API | ✅ |
| **N-4 연관분석** | **Apriori/FP-Growth** — 계수(counting) 알고리즘 | ❌ |
| **N-5 예측** | 이동평균·선형회귀 등 통계 | ❌ |

**흐리면 둘이 어긋난다**: ①**배선을 잘못 공유한다** — N-4·N-5 는 `global/ai` 도 API 키도 타임아웃
폴백도 필요 없다. ⚠ **N-1 을 먼저 한다고 N-4 가 쉬워지지 않는다.** ②**결과의 성격을 착각한다** —
LLM 이 «지어내는» 것과 알고리즘이 «세는» 것은 다르다.

### 4-2. 🔴 N-4 의 함정 — **내가 심은 규칙을 도로 찾는다**

생성 데이터로 연관분석을 돌리면 나오는 규칙은 **전부 N-6 이 심은 것**이다. 「A 를 산 사람은 B 를
산다」가 나와도 그것은 고객에 대한 발견이 아니라 **생성기 설정의 반향**이다.
⚠ **이것을 잊으면 «우리 고객은 …» 이라는 문장이 생기고, 그 문장은 거짓이다.**

**그래서 목적을 바꿔 적었다:**

| 얻는 것 | 어떻게 |
|---|---|
| ✅ **구현이 맞는지** | 🔴 **정답셋이 내장된다** — 심은 규칙을 정답으로 두고 알고리즘이 되찾는지 본다. ⚠ **실데이터로는 못 하는 검증**이다(정답을 아무도 모른다) |
| ✅ 파이프라인·성능 | 배치 시간, 상품 수가 늘 때 조합 폭발이 어디서 터지나 |
| ❌ 고객에 대한 앎 | **못 얻는다** — 안 심은 규칙은 안 나오고 심은 규칙은 반드시 나온다 |

⚠ **표시 규칙**: 생성 데이터 결과를 **고객 화면의 「함께 구매한 상품」으로 띄우지 않는다.**
