### 2-3. 통합이 못 보던 자리 — 여기가 이 작업의 값이다

통합테스트는 마지막에 `SUM(amount) == balance` 로 대조한다. 강력하지만 **못 보는 게 있다**:

1. **부호 오류를 못 잡는다.** `PointHistory.used()` 가 음수를 붙이는데, 양수로 적어도
   *잔액 캐시와 합계가 함께 틀리면* 대조는 통과한다. 이력의 `type`·부호를 **직접 보는 건 단위뿐**이다.
2. **승급 직후 요율.** 누적 99,000 인 회원이 10,000 원을 확정하면 SILVER 로 올라 **200P**(BRONZE 면 100P).
   *"적립률은 누적 반영 **후** 등급으로"* 라는 한 줄이 지켜지는지는 **이 한 케이스에서만** 갈린다.
3. **실패 경로에 이력이 남지 않는가.** 잔액 부족으로 예외가 났는데 원장에 줄이 생기면 합계가 갈라진다.
   행복 경로만 지나는 통합은 이 경로에 들어가지도 않는다.
4. **`Math.max` 가 두 군데** 걸린 반품 순변동 — 잔액 쪽과 이력 쪽. 한쪽만 지워도 정상 케이스는 멀쩡하다.

### 2-4. ⚠ 테스트가 진짜 잡는지 — **일부러 망가뜨려 확인했다**

백로그 H-5 가 못 박은 문장이 있다: *"AI 는 **단언 없는 테스트를 아주 빠르게 대량 생산**할 수 있다.
숫자는 오르고 안전은 안 오른다."* 53건을 새로 쓴 사람이 스스로 *"잘 덮었다"* 고 말하는 건 그 경고에
정확히 걸린다. 그래서 **운영 코드를 5가지로 망가뜨려 빨개지는지** 봤다.

| # | 망가뜨린 곳 | 무엇이 되는가 | 실패 건수 |
|---|---|---|---|
| 1 | `MemberGrade.of` 의 `>=` → `>` | 100,000원 정확히 쓴 사람이 승급 못 함 | **6** |
| 2 | 적립률을 `addPurchase` **앞**에서 계산 | 승급한 주문에 옛 등급 요율 적용(200P → 100P) | **1** |

## 3. G-1 아이디 찾기 — **완료** (배포 대기)

### 3-1. 왜 이걸 골랐나

7/30 문서는 이 자리에 **B-15(문의 답변 알림)** 를 두 번째로 뒀는데 **한 칸 올렸다**(WA §1-2 — 바꿨으면
바꿨다고 말한다). 알림을 못 받는 것보다 **아예 로그인할 방법이 없는 것**이 무겁다:
비밀번호 재설정은 **아이디를 알아야** 시작되므로, 아이디를 잊은 사람은 재설정도 못 한다.

**실측**(착수 전): `/api/auth/*` 는 `signup·login·refresh·logout·me·password-reset/{request,confirm}`
**7개뿐**. 찾기 경로가 정말로 없다.

### 3-2. 설계 — 재설정에서 정한 규칙을 그대로 물려받는다

| 규칙 | 재설정(B-10, 7/28~30) | 아이디 찾기(G-1) | 왜 같은가 |
|---|---|---|---|
| 열거 방지 | 없는 아이디도 **200** | 없는 주소도 **200** | 응답이 갈리면 그게 곧 가입 여부 조회 API 다 |
| 값의 전달 | 링크를 **메일로** | 아이디를 **메일로** | 화면에 띄우면 주소만 넣어 보며 계정을 수집할 수 있다 |
| 요청 제한 | 아이디 3 / IP 10 · 10분 | **주소 3 / IP 10 · 10분** | 성공 하나가 **메일 한 통**이라 비용이 성공에 붙는다 |
| 카운트 시점 | **조회 전** | **조회 전** | 조회 뒤에 세면 429 가 "그 계정은 있다" 를 알려준다 |

**⚠ 한 가지는 일부러 다르게 했다** — 재설정은 dev 에서 토큰을 응답에 실어 화면에 보여준다
(`auth.password-reset.expose-token`). 아이디 찾기엔 **그 갈래를 만들지 않았다**:
**저건 링크지만 이건 신원**이다. dev 확인은 Mailpit 로 한다.

### 3-3. ⚠ 가드를 재설정 것과 공유하지 않은 이유

처음엔 `PasswordResetRequestGuard` 를 그대로 쓰려 했는데 **못 쓴다** — 저쪽은 **아이디**를 세고
여기는 **이메일**을 센다. 억지로 합치면 더 나쁘다: **아이디 찾기를 세 번 하면 비밀번호 재설정
예산까지 소진**돼, 아이디를 되찾은 사람이 곧바로 비밀번호를 못 바꾼다.
→ 공유하는 것은 **카운터 구현**(`AttemptCounter`)이고 **정책(키·임계값)은 각자** 갖는다.
7/30 에 `AttemptCounter` 를 뺀 판단이 바로 여기서 값을 했다(새 가드는 키 2개 + 임계값 3줄이 전부다).

### 3-4. 만든 것

**백엔드**
- `POST /api/auth/find-id` — `{email}` → 항상 `200 {success:true}`. `/api/auth/**` 는 기본 공개라
  SecurityConfig 변경 없음(인증이 필요한 건 `/me`·`/logout` 뿐).
- `FindLoginIdGuard`(신규) · `ErrorCode.TOO_MANY_FIND_ID_REQUESTS`(**AUTH-429F**) ·
  `FindLoginIdRequest`(응답 DTO 는 **없다** — 돌려줄 것이 없는 게 설계다) ·
  `MemberRepository.findByEmail` · `AuthService.findLoginId`.
- ⚠ **정지된 계정도 알려준다.** 아이디는 계정 상태와 무관한 **식별자**이고, 안 알려주면 정지된 사람이
  "왜 안 되는지" 물어볼 창구조차 못 찾는다(로그인하면 403 으로 사유가 안내된다).

**프론트엔드**
- `/find-id`(`FindIdView.vue`) — 재설정 화면과 **같은 골격**(`page-narrow` + `max-w-sm` 카드).
- 로그인 화면 하단을 **「아이디 찾기 | 비밀번호를 잊으셨나요?」** 두 갈래로.
- 재설정 화면에도 **아이디 찾기 링크**를 걸었다 — 아이디를 잊은 사람이 거기서 막히면 갈 곳이 없다.
