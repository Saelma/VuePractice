## 1. 한 일 — P6SPY (실제 SQL + 바인딩값 + 실행시간 로깅)

QueryDSL 동적쿼리·N+1을 육안으로 확인하려고 JDBC를 가로채는 P6SPY를 붙였다. **dev 프로파일에서만** 동작하고 운영엔 영향이 없다.

### 방식 결정 — 왜 starter가 아니라 plain p6spy인가
- ARCHITECTURE §6.0엔 `p6spy-spring-boot-starter`(gavlyukovskiy)로 적혀 있었으나, 이 프로젝트는 **Spring Boot 4.1.0**(막 나온 버전)이라 그 스타터의 자동설정이 Boot 4와 호환될지 불확실했다. (이미 springdoc 2.x→3.x 자동설정 트랩을 겪은 전례.)
- 그래서 **자동설정에 의존하지 않는** 방식으로 붙였다: **dev 프로파일에서 datasource URL만 `jdbc:p6spy:oracle:…`로 바꾸고 드라이버를 `P6SpyDriver`로 교체.** p6spy가 `p6spy:` 접두사를 떼고 실제 Oracle 드라이버로 위임한다.
- **운영(기본 프로파일)** 은 base `application.yml`의 순수 oracle URL을 그대로 써서 **p6spy 코드 경로를 아예 타지 않는다.** → systemd 유닛·배포 스크립트 무수정.

### 변경 파일 (3개)
| 파일 | 내용 |
|---|---|
| `glassvue-backend/build.gradle` | `runtimeOnly 'p6spy:p6spy:3.9.1'` |
| `glassvue-backend/src/main/resources/application-dev.yml` (신규) | dev 한정 — datasource `url`을 `jdbc:p6spy:oracle:thin:@//…`로, `driver-class-name`을 `com.p6spy.engine.spy.P6SpyDriver`로 오버라이드 |
| `glassvue-backend/src/main/resources/spy.properties` (신규) | p6spy 로깅 설정 (아래) |

### spy.properties 핵심
- `driverlist=oracle.jdbc.OracleDriver` — 위임할 실제 드라이버.
- `appender=…Slf4JLogger` — SLF4J로 로깅 (System.out 금지 규칙과 일관, 로거명 `p6spy`).
- `logMessageFormat=…CustomLineFormat` + `customLogMessageFormat=%(executionTime)ms | %(category) | conn %(connectionId) | %(sqlSingleLine)` — 한 줄, 바인딩 인라인된 실제 SQL.
- `excludecategories=info,debug,result,resultset,batch` — **결과셋(result/resultset) 제외 = 민감정보 로깅 방지.** 남기는 것: statement·commit·rollback.

### dev로 켜는 법
```bash
set -a; . /home/ecstel/work/.env; set +a
SPRING_PROFILES_ACTIVE=dev ./gradlew bootRun
# 또는 jar:  SPRING_PROFILES_ACTIVE=dev java -jar glassvue-backend.jar
```
프로파일 안 주면(=운영) p6spy 미로딩. **배포/systemd 손댈 필요 없음.**

## 2. 검증 (실측)

운영 서비스(:8080)를 안 건드리게 **:8081**로 dev 인스턴스를 띄워 확인:

- **바인딩 인라인 + 실행시간** ✅ — notice 제목검색 시:
  ```
  43ms | statement | conn 0 | select … from notice n1_0
        where lower(n1_0.title) like '%공지%' escape '!'
        order by n1_0.pinned desc, n1_0.created_at desc
        offset 0 rows fetch first 3 rows only
  ```
  `?`가 아니라 실제 값(`공지`)이 인라인, 실행시간(43ms)까지.
- **페이징/카운트 쿼리 분리**도 그대로 보임(목록 166ms + count 12ms).
- **운영 무영향** ✅ — 기동 중이던 :8080 서비스의 journal p6spy 라인 **0개**.

## 3. 트랩 · 교훈

- **Boot 4 + 서드파티 자동설정 = 상습 지뢰.** p6spy도 starter(자동설정) 대신 **URL 재작성**이라는 자동설정-무의존 경로를 택해 회피. (springdoc 트랩의 연장선)
- **p6spy는 classpath에 spy.properties가 있어도**, datasource URL이 `jdbc:p6spy:…`가 아니면 아무 일도 안 한다 → 운영 프로파일 격리가 URL 하나로 깔끔히 됨.
- **결과셋 로깅 = 민감정보 유출.** `excludecategories`에 result/resultset 넣어 SQL·시간만 남기고 데이터는 안 찍음.
- dev 인스턴스 검증은 **포트만 바꿔(:8081)** 띄우면 운영(:8080) 무중단으로 가능.

## 4. 상품 리뷰/문의 도메인 (review · inquiry) — 신규

ARCHITECTURE §5 도메인 로드맵의 다음 순서(order → review/inquiry). 게시판(CRUD·페이징·정렬 화이트리스트·소유권/ADMIN·QueryDSL)+이커머스(order) 패턴을 이식. **polymorphic FK 없이 도메인별 별도 테이블**, 상품엔 느슨한 UUID 참조.

### review (`domain/review`)
- `Review`(product_id·author_id 느슨참조, rating 1~5, content). **구매자만 작성** — `OrderService.hasPurchased(memberId, productId)`(공개 API, 취소 안 된 ORDERED 주문 확인)로 인증, **상품당 1회**(`existsByProductIdAndAuthorId`). 수정·삭제는 본인 또는 ADMIN.
- 상품별 목록 + **요약(평균 별점·개수)** = `ProductReviewsResponse{averageRating, reviewCount, page}`. 집계는 리뷰 도메인 JPQL(`avg`,`count`), **product는 안 건드림**. 정렬 화이트리스트(createdAt/updatedAt/rating).
- 엔드포인트: `POST/GET /api/products/{id}/reviews`, `PUT/DELETE /api/reviews/{id}`.

### inquiry (`domain/inquiry`)
- `Inquiry`(secret 비밀글, status WAITING/ANSWERED, answer/answeredAt). 작성 로그인 필요, **답변은 ADMIN 전용 + 본인 문의 제외**(질문자≠답변자, `INQUIRY_SELF_ANSWER` 403 — `77fd508`), 비밀글은 작성자·ADMIN 외 **본문/답변 마스킹(응답 DTO `InquiryResponse.from(i, viewer)`, masked=true)**. 수정은 본인+답변 전만, 삭제는 본인 또는 ADMIN.
- 목록은 공개(`@LoginUser(required=false)`로 viewer 판단). 엔드포인트: `POST/GET /api/products/{id}/inquiries`, `PUT/DELETE /api/inquiries/{id}`, `POST /api/inquiries/{id}/answer`(ADMIN).

### 도메인 경계
- 리뷰→catalog(`ProductQueryService.ensureExists`)·order(`OrderService.hasPurchased`), 문의→catalog. **전부 공개 서비스로만** 호출(리포지토리 직접참조 회피). ErrorCode 7종·SecurityConfig 라우팅 추가.

### 프론트 (`components/ProductReviews.vue`·`ProductInquiries.vue`)
- 상품 상세(ProductDetailView) 하단에 삽입. 리뷰: 요약·별점목록·클릭별점 작성폼·본인/ADMIN 수정삭제·페이지네이션. 문의: 상태배지·🔒비밀글·비밀글 마스킹 표시·관리자 답변폼. `api/review.js`·`api/inquiry.js`(client.js 재사용).

### 검증
- **백엔드 E2E(curl, dev :8081)**: 미구매 리뷰 403→구매후 201→중복 409→별점 400, 비밀글 익명 마스킹/작성자 열람, USER 답변 403/ADMIN 답변 200→ANSWERED, 답변후 수정 400, 정렬 화이트리스트 400. 전부 통과.
- **브라우저 E2E(playwright chromium, dev :3000→:8081)**: 로그인 상태별(익명/USER/ADMIN) 렌더링 + 리뷰 작성 해피패스(별점→제출→요약 갱신) 캡처 검증. → **DxTextBox 렌더 버그 발견·수정**(아래 트랩).

### 트랩
- **DevExtreme `DxTextBox`를 일반 block 컨테이너에 두면 입력 높이를 오측정**해 720px로 깨진다. 정상 동작하는 `NoticeFormView`처럼 **직속 부모를 `flex flex-col`**로 감싸면 34px 정상. 빌드만으론 못 잡고 브라우저 렌더로만 발견됨(`12a8787`).
- **playwright chromium**은 이 서버에서 시스템 라이브러리 추가 없이 헤드리스 구동됨(sudo 불필요). scratchpad에 pnpm으로 격리 설치(저장소 무오염).
