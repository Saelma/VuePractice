## 2. 구현

### 2-1. 단발성 토큰 — `PasswordResetTokenStore` (Redis, `RefreshTokenStore` 와 키 방향 반대)

- key=`auth:reset:<token>`, value=`memberId`, TTL 30분(`auth.password-reset.token-validity-ms`).
- ⚠ **토큰을 키로 둔다**(회원당 1개가 아니라 **토큰당 1개**). refresh 는 회원당 1개(회전)라 회원 id 가 키지만,
  재설정은 재발급이 이전 링크를 조용히 무효화하면 안 되고, 소비 때 토큰만으로 O(1) 삭제돼야 한다.
- `consume` = `getAndDelete`(GETDEL, 원자) → **단발성**. 동시에 두 번 소비돼도 값을 받는 쪽은 하나뿐이라 경합 안전.
- 토큰 문자열은 `UuidCreator.getTimeOrderedEpoch()`(BaseTimeEntity·restock 과 같은 생성기).

### 2-2. `AuthService` 두 메서드

- `requestPasswordReset(loginId): Optional<String>` — 회원 있으면 토큰 발급해 반환, **없으면 empty**.
  호출자(컨트롤러)는 이 둘을 구분해 사용자에게 드러내지 않는다(**열거 방지**).
- `confirmPasswordReset(token, newPassword)` — `consume` 으로 검증(없으면 `INVALID_RESET_TOKEN`) →
  `updatePassword(encode)` → `refreshTokenStore.delete(memberId)`(다른 세션 무효화, `MemberService.changePassword`
  와 동일 규칙: 비번 바뀌면 재로그인).

### 2-3. 엔드포인트 (둘 다 공개 — 기본 permitAll)

- `POST /api/auth/password-reset/request` `{loginId}` → 항상 200. `PasswordResetResponse{token}` 인데
  **`expose-token` 이 true 일 때만** 토큰을 싣는다(아니면 null). 컨트롤러가 노출을 게이트(서비스는 늘 발급).
- `POST /api/auth/password-reset/confirm` `{token, newPassword(@Size 8~64)}` → 200 / 400(`AUTH-400R`).
- SecurityConfig 변경 **불필요** — 기본이 `.anyRequest().permitAll()` 이라 `/api/auth/password-reset/**`
  는 자동 공개(로그인 전 접근이라 의도한 대로). 새 ErrorCode `INVALID_RESET_TOKEN("AUTH-400R", 400)`.

### 2-4. 설정 — 프로파일로 노출 격리

- `application.yml`(기본=운영): `auth.password-reset.expose-token: false`, `token-validity-ms: 1800000`.
- `application-dev.yml`: `expose-token: true` 오버라이드. `PasswordResetProperties`(@ConfigurationProperties,
  `@ConfigurationPropertiesScan` 으로 자동 등록 — JwtProperties 와 달리 SecurityConfig 명시 등록 불필요).

### 2-5. 프론트 — 요청/확정 두 화면 (공개 라우트)

- `views/ForgotPasswordView.vue`(`/forgot-password`): 아이디 입력 → 요청 → "링크 보냈습니다"(열거 방지 문구).
  **dev 는 응답 토큰이 있어** `/reset-password?token=…` 링크를 화면에 바로 띄운다(발송 대체). 운영은 token 이
  null 이라 그 블록이 안 뜬다.
- `views/ResetPasswordView.vue`(`/reset-password?token=`): 새 비번 2회 입력(8자·일치 검사) → confirm →
  "변경됨, 로그인하세요".
- `api/auth.js`: `requestPasswordReset`/`confirmPasswordReset`. `router/index.js`: 두 공개 라우트(`requiresAuth` 없음).
  `LoginView`: "비밀번호를 잊으셨나요?" 링크.

### 브라우저 검증 스텝 (배포 후)

1. 로그인 화면 → "비밀번호를 잊으셨나요?" → `/forgot-password`.
2. 내 아이디 입력 → 요청. **dev/로컬**이면 화면에 `/reset-password?token=…` 링크가 뜬다(운영은 안 뜸).
3. 그 링크 → 새 비번 2회 입력 → 변경.
4. **옛 비번 로그인 → 실패**, **새 비번 로그인 → 성공**.
5. 없는 아이디로 요청 → 똑같이 "보냈습니다"(열거 안 됨).
